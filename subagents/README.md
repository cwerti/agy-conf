# AI Subagents Catalog

Субагенты (Subagents) — это специализированные автономные копии агента с изолированным контекстным окном, собственной ролью и системным промптом. Они запускаются параллельно в фоне для решения узких задач без загрязнения основного диалога и перерасхода токенов.

---

## 👥 Доступные базовые субагенты

| Субагент | Роль | Доступ к инструментам | Когда использовать |
| :--- | :--- | :--- | :--- |
| **`code-reviewer`** | Senior Python & FastAPI Code Reviewer | **Read-Only** (чтение кода, MCP) | Проведение код-ревью перед коммитом или созданием MR/PR, проверка соблюдения Pydantic v2, отсутствия блокирующего I/O и N+1 queries. |
| **`database-architect`** | PostgreSQL & SQLAlchemy 2.0 Specialist | **Read + Write** (миграции, MCP Postgres) | Анализ и генерация миграций Alembic, аудит медленных запросов (`EXPLAIN ANALYZE`), проектирование индексов и схем таблиц. |
| **`api-tester`** | QA Automation Engineer (Pytest) | **Read + Write** (создание тестов, запуск pytest) | Написание асинхронных тестов эндпоинтов FastAPI (`pytest-asyncio`, `httpx`), покрытие граничных случаев, HTTP 422 и негативных сценариев. |
| **`debugger`** | Senior Backend Troubleshooter | **Read + Write** (отладка, воспроизведение) | Глубокий анализ сложных трейсбеков, логов Docker контейнеров, локализация трудновоспроизводимых плавающих багов в изолированном контексте. |

---

## 🚀 Как вызывать субагентов

Агент может делегировать задачу субагенту самостоятельно, либо вы можете прямо попросить в чате:

* *"Запусти code-reviewer для проверки последних изменений"*
* *"Пусть database-architect проверит схему миграции перед накатом"*
* *"Поручи api-tester написать тесты для нового эндпоинта"*
* *"Подключи debugger, чтобы разобрать этот трейсбек ошибки"*

Субагент выполняет задачу в фоне, не занимая ваш основной контекст, и возвращает готовый структурированный результат.
